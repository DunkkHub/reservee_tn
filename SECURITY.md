# Security Policy

## Reporting a vulnerability

Please do not open public issues for suspected security vulnerabilities.

Instead:

1. Email the repository owner or the product/security contact configured for this project.
2. Include reproduction steps, impact, affected routes, and any required environment details.
3. Allow reasonable time for triage before public disclosure.

## What to include

- vulnerability type
- affected endpoint or page
- prerequisites
- proof of concept or request sample
- expected impact
- suggested mitigation if known

## Response expectations

- acknowledgement of receipt
- severity triage
- remediation plan or request for clarification
- coordinated disclosure once fixed
